Conceptual Guide · NLP Fundamentals

How Tokenisation Works in LLMs

Audience: developers new to NLP Reading time: ~10 min

LLMs do not read text the way humans do. Before any prediction happens, your input is split into tokens — discrete units the model processes one at a time. Understanding this step changes how you write prompts and interpret model behaviour.

What is a token?

A token is the smallest unit of text a language model processes. Tokens are not always words. Depending on the tokeniser, a token might be:

  • A full word: apple
  • A word fragment: un, ##expected
  • A punctuation mark: ., ?
  • A whitespace character

The model never sees your raw text. It sees a sequence of integer IDs, each corresponding to a token in the model's vocabulary.

From text to token IDs

When you send a prompt, the following happens before the model processes anything:

Input text
"The cat sat on the mat."
↓ tokeniser
Tokens
[ "The", " cat", " sat", " on", " the", " mat", "." ]
↓ vocabulary lookup
Token IDs
[ 464, 4758, 3332, 319, 262, 2603, 13 ]
↓ embedding layer
Dense vectors → model input

The mapping from token to ID is fixed — it is defined by the tokeniser the model was trained with and does not change at inference time.

Subword tokenisation

Early NLP systems used either character-level or word-level tokenisation. Both have significant drawbacks:

  • Character-level: sequences become very long; relationships between characters are hard to learn.
  • Word-level: the vocabulary must be enormous to handle every word form; rare words are missed entirely.

Modern LLMs use subword tokenisation, which splits text at the level of meaningful fragments. Common subword algorithms include Byte Pair Encoding (BPE), used by GPT models, and WordPiece, used by BERT.

How BPE works

BPE starts with individual characters and iteratively merges the most frequent adjacent pairs. The result is a vocabulary where common words appear as single tokens and rare words are broken into recognisable pieces.

For example, the word unbelievable might tokenise as:

untok 946
beltok 2071
ievtok 494
abletok 540

Whereas a common word like table is a single token:

tabletok 3084
Note: Token boundaries do not always align with morpheme boundaries. The split is statistical, not linguistic. unbelievable might split differently depending on the tokeniser and what was common in the training corpus.

Vocabulary size and coverage

A model's vocabulary is the full set of tokens it knows. Vocabulary sizes typically range from 32,000 to 100,000+ tokens. Larger vocabularies mean:

  • Fewer tokens needed to represent a given text (more efficient)
  • More parameters in the embedding layer (larger model)
  • Better coverage of rare and domain-specific words

OOV and unknown tokens

An out-of-vocabulary (OOV) token is any string not in the model's vocabulary. With subword tokenisation, true OOV situations are rare — most strings can be decomposed into known subword units. However, edge cases include:

  • Very unusual Unicode characters
  • Strings in scripts not represented in the training data
  • Extremely long tokens with no valid splits

When a tokeniser cannot represent a string, it falls back to a special [UNK] token. Information is lost at this point — the model receives no signal about the original characters.

Tip: If a model consistently misreads a proper noun or technical term, it may be tokenising it in an unusual way. Try including the term in a context sentence earlier in your prompt, or experiment with alternative spellings.

Implications for prompting

Tokenisation has several practical effects on how models interpret and generate text.

Token count ≠ word count

Context window limits are measured in tokens, not words. As a rough rule of thumb, one token is approximately 0.75 words in English. Technical content, code, and non-English text tokenise differently:

  • English prose: ~1.3 tokens per word
  • Python code: ~1.5–2 tokens per word (operators and indentation add tokens)
  • Chinese or Arabic: 2–4 tokens per character, depending on the tokeniser

Splitting at word boundaries

Many tokenisers encode leading whitespace as part of the token. cat (space + cat) and cat are different tokens. This means the same word may tokenise differently depending on its position in a sentence.

Numbers and special characters

Numbers are often split into individual digits. The string 2024 may become four separate tokens: 2, 0, 2, 4. This is one reason LLMs perform poorly on arithmetic — each digit is processed without inherent positional value.

Summary

Tokenisation converts raw text into the integer sequences that LLMs actually process. Key points:

  • Tokens are subword units, not words — boundaries are statistical, not linguistic.
  • Every model has a fixed vocabulary defined by its tokeniser.
  • Context window limits are measured in tokens; non-English text is typically less efficient.
  • Understanding tokenisation helps explain why models sometimes misread unusual names, handle numbers poorly, or treat punctuation unexpectedly.

Getting Started Guide · Corpus Linguistics

Getting Started with AntConc

Audience: linguists and researchers Time to complete: ~30 min AntConc 4.x

AntConc is a free corpus analysis toolkit used for concordancing, collocation analysis, and frequency profiling. This guide takes you from installation to your first concordance search.

Before you begin

You will need:

  • A computer running Windows 10+, macOS 10.14+, or Linux (Ubuntu 18.04+)
  • At least one plain text file (.txt) to use as a corpus
  • Approximately 15 minutes for installation and setup
Note: AntConc works with plain text files only. If your source material is in .docx, .pdf, or another format, you must convert it to .txt before loading it. Encoding should be UTF-8 for best results with non-ASCII characters.

Installation

  1. Go to laurenceanthony.net/software/antconc and click Download.

    Select the installer for your operating system. The download is approximately 50 MB.

  2. Windows: Run the downloaded .exe installer and follow the prompts. Accept the default installation directory.

    macOS: Open the .dmg file and drag AntConc to your Applications folder. On first launch, right-click and select Open to bypass Gatekeeper.

    Linux: Extract the .tar.gz archive and run ./AntConc from the extracted folder.

  3. Launch AntConc. The main window opens with an empty file list on the left and a blank concordance view on the right.

Loading a corpus

A corpus in AntConc is a collection of one or more plain text files. You can load a single file or an entire directory.

  1. From the menu bar, select File → Open File(s) to load individual files, or File → Open Dir to load all .txt files in a folder.

  2. Navigate to your corpus files and select them. Loaded files appear in the Corpus Files panel on the left.

  3. Check the file count and total tokens in the status bar at the bottom. If the count looks wrong, verify that your files are saved as UTF-8 plain text.

Tip: For multilingual corpora, go to Tool Preferences → Token Definition and make sure Unicode character classes are enabled. This ensures correct tokenisation of non-Latin scripts.

Running a concordance search

A concordance shows every instance of a search term in context — one line per occurrence, with the keyword centred.

  1. Click the Concordance tab at the top of the main window.

  2. Type your search term in the Search Term field. For example: argue

  3. Click Start or press Enter. Results appear in the concordance view, sorted by file by default.

  4. To sort results by the word immediately to the left or right of your search term, use the Sort controls. This helps identify common collocations at a glance.

Using wildcards

AntConc supports the following wildcard characters in search terms:

CharacterMatchesExample
*Zero or more charactersargu* matches argue, argues, arguing, argument
?Exactly one characterwom?n matches woman and women
|Either pattern (OR)cat|dog matches either word

Collocate analysis

The Collocates tool finds words that co-occur with your search term more often than chance.

  1. Click the Collocates tab. Your previous search term carries over.

  2. Set the window span — how many words to the left and right of the keyword to consider. A span of 3L/3R is standard for most analyses.

  3. Click Start. Results are ranked by frequency by default. Click the Stat column header to sort by statistical significance (mutual information or t-score).

Note: AntConc reports raw frequency and two association measures: MI (Mutual Information) and t-score. MI favours rare but distinctive collocates; t-score favours frequent collocates. Which to use depends on your research question.

Generating a word list

The Word List tool produces a frequency-ranked list of all tokens in your corpus.

  1. Click the Word List tab and then click Start.

  2. To remove function words from the results, go to Tool Preferences → Word List → Lemma List and load a stopword file. AntConc accepts plain text stopword lists with one word per line.

  3. To export results, right-click anywhere in the word list and select Save Output to Text File. The output is a tab-separated file you can open in Excel or import into R.

Next steps

Once you're comfortable with basic concordance searches and word lists, explore these tools:

  • N-Grams: Find the most frequent sequences of 2, 3, or 4 words in your corpus.
  • Keyword List: Compare your corpus against a reference corpus to identify statistically unusual words. Requires loading a reference corpus via File → Open Reference Corpus Dir.
  • Clusters/N-Grams: Identify recurring multi-word units.

Full documentation is available at laurenceanthony.net/software/antconc under the Help section.

API Reference · Met Museum Collection API

Met Museum Collection API

Version: 1.0 Base URL: collectionapi.metmuseum.org Auth: none required

The Metropolitan Museum of Art Collection API provides programmatic access to over 470,000 objects in the Met's collection, including images, provenance data, and classification metadata. No API key is required.

Base URL and authentication

All requests use the following base URL:

https://collectionapi.metmuseum.org/public/collection/v1

The API is public and does not require authentication. There are no published rate limits, but the Met requests that you avoid making requests at high frequency. A delay of 200–500 ms between requests is recommended for bulk operations.

Note: The API returns JSON only. All responses are UTF-8 encoded. CORS is enabled, so the API can be called from browser-based applications.

Search objects

Returns a list of Object IDs matching your query. Use the returned IDs with the Get Object endpoint to retrieve full records.

GET /search

Searches the collection by keyword. Returns an array of matching Object IDs.

Query parameters

ParameterTypeRequiredDescription
q string required Search term. Searches across title, artist name, tags, and other text fields.
isHighlight boolean If true, returns only objects designated as Met highlights. Default: false.
departmentId integer Limits results to a specific department. See Departments for valid IDs.
hasImages boolean If true, returns only objects with at least one primary image. Default: false.
medium string Filters by medium or object type. Examples: Paintings, Sculpture, Drawings. Case-sensitive.
geoLocation string Filters by geographic location. Examples: France, Japan. Searches the country, region, and city fields.
dateBegin integer Start of date range (year). Use negative values for BCE. Requires dateEnd.
dateEnd integer End of date range (year). Requires dateBegin.

Response

{

  "objectIDs": [
    437984,
    436105,
    438821,
    ...
  ]
}
FieldTypeDescription

Error handling

Status codeMeaningCommon cause
200OKRequest succeeded.
400Bad RequestMissing required parameter (e.g., q on Search, objectID on Get Object).
404Not FoundThe specified objectID does not exist or has been removed from the collection.
500Internal Server ErrorServer-side error. Retry after a short delay.
Note: The API does not return a JSON error body. On error, only the HTTP status code is returned. Check the status code before parsing the response body.

Full examples

Find public-domain paintings from Japan with images

Request
curl "https://collectionapi.metmuseum.org/public/collection/v1/search?q=landscape&geoLocation=Japan&hasImages=true&medium=Paintings&departmentId=6"
Python
import requests

BASE = "https://collectionapi.metmuseum.org/public/collection/v1"

# Search for landscape paintings from Japan
search = requests.get(f"{BASE}/search", params={
    "q": "landscape",
    "geoLocation": "Japan",
    "hasImages": True,
    "medium": "Paintings",
    "departmentId": 6
})
search.raise_for_status()
object_ids = search.json().get("objectIDs", [])

# Fetch the first result
if object_ids:
    obj = requests.get(f"{BASE}/objects/{object_ids[0]}")
    obj.raise_for_status()
    data = obj.json()
    print(data["title"], "—", data["artistDisplayName"])
    print("Image:", data["primaryImage"])
